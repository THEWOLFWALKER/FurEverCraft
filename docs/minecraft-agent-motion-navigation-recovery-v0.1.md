## 1. 本轮范围与决策

本轮把“模型会决策、运行时会执行”落实为动作合同、运动状态、导航图、控制资源、交接与故障处理。只写设计，不安装软件、不搜索、不假定结构化接入已经完成。

延续：真实客户端、无客户端 Mod、无服务端权限、结构化优先、视觉按需、OpenAI/Anthropic 通用模型 API、不训练控制模型。

决策：

1. 模型调用技能工具；本地动作原语持续执行，不把每次按键变成 API 请求。
2. 规划器仅生成已有控制器能够尝试执行的动作边，未验证能力明确标为实验性。
3. 每个动作有阶段、阶段进展、结束证据和交接条件。
4. 平地、水中、空中、攀爬与 UI 不共用“全松键即安全”的假设。
5. 运行时同时检查发送时效与观测时效；命令晚到不能通过重新计算 TTL 变新。
6. 动作和副作用分离：控制可结束，但效果核对可以继续。
7. 恢复也是受资源与期限管理的执行实例，不能形成后台隐藏的第二个控制器。

## 2. 技能、原语、输入的边界

| 层 | 示例 | 负责 | 不负责 |
|---|---|---|---|
| 任务 | 收集材料建住所 | 目标、依赖、预算、里程碑 | 逐帧转向 |
| 技能 | navigate、harvest、craft、build_segment | 原语组合、前置条件、进展、恢复 | 直接调用 OS 输入 |
| 动作原语 | walk_corridor、jump_to_region、place_one | 阶段与闭环、局部目标、终态 | 修改长期目标 |
| 输入计划 | 按键集合、鼠标增量、点击 | 有限时、具体输入 | 宣称世界效果完成 |

原语可由确定性算法、有限状态机或有界模型动作片段实现。无需用统一行为树强制承载所有内部逻辑；技能层允许小型状态机或行为树，但它们只生成受控原语请求。

## 3. 身体模式与观测有效性

身体模式是状态估计，不是向客户端写一个 enum 就能切换姿态：

```text
GROUND / AIR / WATER / CLIMB / UI / INCAPACITATED / UNKNOWN
```

UI 是交互模式；玩家开界面时仍可能处于水中或空中。因此实际状态保存两个轴：physicalMode 和 interactionMode，而不是互斥的单一模式枚举。

| 模式 | 主要证据 | 不足时的处理 |
|---|---|---|
| GROUND | 客户端接地报告、脚下支撑、位置变化 | 冲突时不启动要求精确起跳的动作 |
| AIR | 支撑丢失、位置和速度估计 | 保留不确定性；不能把一次网络样本缺失当下落 |
| WATER | 当前流体几何、可得姿态/HUD、运动模式 | 氧气未知时不承诺长潜水路径 |
| CLIMB | 接近可攀附面与实际位移 | 未建立接触证据前不认定已攀附 |
| UI | 当前窗口证据、动作上下文、必要截图 | 不把键盘文本发送到不确定界面 |
| INCAPACITATED | 死亡、断线、无法控制状态 | 撤销动作，转生命周期恢复 |

模式冲突触发重新观察和能力收缩，不自动强制截图。优先核对已有结构化来源；仍无法消解且视觉有帮助时才请求画面。

## 4. 原语合同

以下类型描述领域语义，不是可以直接运行的代码。

```ts
interface PrimitiveSpec {
  id: string;
  version: string;
  implementationId: string;
  parameterSchemaRef: string;
  requiredCapabilities: string[];
  acceptedPhysicalModes: string[];
  requiredInteractionMode: string;
  entryPredicates: string[];
  invariants: string[];
  resources: string[];
  progressPolicyRef: string;
  terminationPolicyRef: string;
  handoffPolicyRef: string;
  effectClass: 'motion' | 'interaction' | 'world-mutation' | 'message';
  testedProfileRefs: string[];
}

interface PrimitiveInvocation {
  id: string;
  executionId: string;
  primitiveId: string;
  primitiveVersion: string;
  parameters: unknown;
  snapshotRef: string;
  dependencyRefs: string[];
  controlLeaseRefs: string[];
  budgetRef: string;
}

interface PrimitiveFeedback {
  invocationId: string;
  phase: string;
  progress: { kind: string; value?: number; evidenceRefs: string[] };
  status: 'running' | 'stopping' | 'verifying' | 'settled';
  terminalReason?: string;
  effectRefs: string[];
  nextHandoff: 'now' | 'at-phase-boundary' | 'recovery-required' | 'unknown';
}
```

动作不能自行申请无限期限或扩大风险预算。参数、资源和能力由执行器验证；实际租约由仲裁器授予。

### 4.1 通用状态机

```text
CREATED → CHECKING → WAITING_RESOURCES → EXECUTING
                                       ├→ VERIFYING → SETTLED
                                       ├→ STOPPING → SETTLED
                                       └→ SUSPENDED / RECOVERY_REQUIRED
```

SETTLED 的结果分为成功、失败、取消或控制丢失；effect ledger 独立保存未知副作用。没有进展不立即等于失败：等待区块、等方块响应和等待资源必须有明确原因及期限。

### 4.2 时间与预算

每个实例分别管理资源等待期限、执行期限、阶段无进展期限、效果核对期限。重试预算分布在原语、技能与任务层，但由共享预算对象扣除，禁止每升级一层就重置无限重试。

预算包括时间、材料、允许地形变更与失败次数。生命风险约束属于策略配置；死亡不掉落不代表允许无意义反复死亡。

## 5. 基础原语清单

| 原语 | 入口与阶段 | 成功证据 | 主要恢复 |
|---|---|---|---|
| orient_to | 相机/鼠标映射有效；估计误差→有限转向→核对 | 朝向进入容差域且无冲突 | 校准失效、重新观测 |
| walk_corridor | 已验证走廊；对齐→推进→减速→到达 | 目标域、支撑和允许速度范围 | 局部纠偏、避障、重规划 |
| step_up | 可站立台阶与净空；接近→跨越→稳定 | 新支撑区域成立 | 后退重新定位、换路线 |
| jump_to_region | 支撑、助跑、落点、头顶净空；助跑→起跳→飞行→落地 | 落脚域与稳定状态 | 当前相位继续控制或恢复落地 |
| controlled_drop | 可验证落点与风险；对齐→离开支撑→下落→稳定 | 目标支撑或水中终态 | 空中修正、风险升级 |
| swim_to_surface | 水中与可呼吸方向；上浮→呼吸/保持 | 头部离水等可用证据 | 绕开顶部障碍、换呼吸点 |
| swim_to_region | 水中路线；保持姿态→水平/垂直推进 | 目标域与可持续状态 | 换方向、上浮、找浅滩 |
| exit_water | 当前水岸几何与落脚点；对齐→贴岸→跨出→稳定 | 地面支撑与泳姿退出证据 | 换岸点、返回水中保持 |
| climb_surface | 可攀面；接触→攀爬→顶部/底部转换 | 稳定脱离或到达攀爬目标 | 重新贴合、受控退出 |
| interact_once | 目标可触达、界面模式合适；瞄准→点击→核对 | 对应状态变化或交互反馈 | 不确定先观察，不盲重复 |
| dig_one | 工具、目标、支撑；选物→瞄准→持续挖→停止→核对 | 目标态变化与相关证据 | 停止持续输入、目标刷新 |
| place_one | 材料、合法面、站位；选物→瞄准→点击→核对 | 目标方块状态及材料证据 | 保持支撑，结果调和 |
| enter_ui / exit_ui | 可交接身体状态；切换→确认 | 预期 UI 模式证据 | UI 未知时暂停依赖输入 |
| click_slot | 窗口版本与布局有效；移动光标→点击→核对 | 槽位更新符合目标 | 窗口重同步、部分效果核对 |
| submit_text | 文本模式明确；输入→提交→退出确认 | 发送请求证据，回执另记 | 不确定不自动重发 |

以上为目标清单，不代表第一版全部可用。原语没有对应验证记录时，不向普通技能目录宣告稳定能力。

### 5.1 跳跃的明确阶段

APPROACH 检查速度与方向 → TAKEOFF 检查是否离开支撑 → AIRBORNE 依据估计修正 → LANDING 检查落脚域 → STABILIZING 检查后续可控状态。

起跳未发生、撞头和落点偏离是不同原因。单纯 y 变大不能证明跳跃正确；客户端上报 onGround 也不能单独证明安全落地。

普通取消尽量延迟到可交接点；紧急取消立即停止旧 owner，并将剩余身体控制交给有对应模式能力的恢复控制器。不能把地面停步控制器用于空中接管。

### 5.2 搭桥是组合技能

`approach_edge → hold_support → orient_to_face → place_one → verify_support → walk_to_new_support`。

每次前移依赖新支撑的当前证据。潜行、视角和放置构成复合资源，不能让聊天技能在桥沿随意抢走键盘。结果未知时保留必要的支撑行为，核对并不意味着冻结所有身体控制。

### 5.3 战斗的扩展边界

将保持距离、跟随、侧移、撤退与攻击动作分别建模，协调视角和交互资源。不以一个 combat=true 开关覆盖导航。

目标持续可见性、目标移动与击退使计划有效期更短。首期可以只提供撤退和有限近战技能；高水平战斗不是这些接口定义后自然成立的能力，需独立场景验证。

## 6. 导航图与规划结果

### 6.1 分层表示

全局层保存地点、区域、入口、传送门与探索边界。局部层保存姿态区域、支撑面和动作转移。

普通地面节点可只使用位置域与支撑面；跳跃等对速度、朝向敏感的动作才扩展相关维度，避免整个地图出现状态组合爆炸。

```ts
interface ActionEdge {
  id: string;
  primitiveId: string;
  primitiveVersion: string;
  startRegionRef: string;
  terminalRegionRef: string;
  entryPredicateRefs: string[];
  dependencyRefs: string[];
  expectedEffects: string[];
  costs: {
    durationEstimateMs?: number;
    materialEstimate?: Record<string, number>;
    damageEstimate?: number;
    uncertainty: 'low' | 'medium' | 'high' | 'unknown';
  };
  admissibility: 'verified-profile' | 'conditional' | 'unsupported';
}
```

verified-profile 表示符合已验证条件，不表示数学保证成功。预计材料与实际库存分别管理。

### 6.2 规划返回值

- COMPLETE：找到当前条件下的候选路线，执行前仍检查局部前提。
- PARTIAL：只承诺到一个可交接区域，附下一段待观察条件。
- NEEDS_OBSERVATION：已知信息不足，返回具体缺口与观察目标。
- BUDGET_EXHAUSTED：搜索预算不足，不等于不可达。
- NO_PATH_IN_KNOWN_GRAPH：当前已知图无解，不等于世界绝对不可达。
- UNSUPPORTED_TRANSITION：存在几何候选，但没有适用控制器。

部分路径若终点无法停稳或保持，不得作为可执行前缀提交。未知区域优先产生探索目标，不直接生成穿越边。

### 6.3 地形变更与依赖

路径记录涉及区域、动作前提、资源及控制器版本。区域变化只使受影响的路径段失效；背包材料不足使依赖放置的边失效；控制器撤销使对应动作边失效。

挖掘和放置会改变未来地形。可在有限局部规划中使用显式“假设已完成效果”，但必须保存在规划假设层。真正执行后续动作前，由新观察替代假设，不能写回 Live State 冒充事实。

全局搜索不无限枚举所有可能施工世界。先生成少量受预算约束的通路方案，再逐段实施与重规划。

## 7. 能力注册与失败经验

能力注册表绑定：原语版本、输入后端、客户端/协议版本、观测能力、模式、地形特征和测试条件。

能力状态：UNVERIFIED、EXPERIMENTAL、ENABLED、DEGRADED、DISABLED。

启用依据必须是记录化验证；模型不能通过调用工具自行将某个原语提升为稳定能力。实验性动作可以在明确预算下尝试，结果归档，不能因一次成功就全局晋升。

失败归因至少区分：

- 图生成或几何解释错误。
- 起始条件不满足。
- 控制执行偏差。
- 观测缺失、延迟或冲突。
- 环境被其他玩家改变。
- 服务端修正或交互拒绝迹象。
- 输入焦点、UI 或客户端健康问题。
- 未知原因。

单次服务器修正不自动归因为作弊检测，也不自动判定所有运动能力失效。

失败经验按范围降权和冷却。成功统计附样本数、条件与失败分类；它是经验，不是承诺的成功概率。恢复或重新验证后可解除临时禁用。

## 8. 控制循环与命令时效

### 8.1 本地循环

```text
读最新一致的局部视图
→ 检查会话、资源与输入通道健康
→ 处理相关修正和前提失效
→ 当前原语计算候选输入
→ 监督器核验模式、期限和条件
→ 网关提交本周期控制
→ 发布进展与诊断
```

无 Mod 时精确客户端 tick 可能不可得，循环按本地单调时间运行，并通过协议/位置变化估计实际响应。循环频率、反馈频率和动作有效频率分别测量，不假称硬实时。

控制循环不等待模型、磁盘、截图编码或语义检索。耗时搜索使用不可变快照在后台进行；返回后检查相关依赖，而非只检查全局 revision 是否完全相同。

### 8.2 修正上一份合同的 TTL 简化

单独使用“接收时起算 validForMs”存在漏洞：排队很久的旧指令到达后会获得新期限。实际准入同时检查：

1. 发送来源、sourceEpoch 和序号。
2. 生成时间与时钟偏移误差界，或对当前网关 challenge 的有效响应。
3. 最大传输/排队年龄。
4. 原始观测年龄与起始状态范围。
5. 网关本地租约期限。

时钟不确定时不得接受要求严格时效的细粒度命令。晚到命令不会因为重新封装或网络重试而延长有效性。

按键集合可取最新有效状态；鼠标相对增量、点击与文本不是可无条件重放的状态。重复 commandId 不再次施加增量，不重复点击。丢失增量反馈时重新测量朝向，不累计补发历史鼠标移动。

### 8.3 模型短动作片段

片段包含锚定快照、起始状态域、目标、有限输入序列、终止条件和交接类型。每个执行周期可提前终止，不能只在片段结束检查。

新片段只替换尚未提交且兼容当前阶段的部分。交互动作前后存在核对屏障；不能用预期放置结果提前安排踩上新方块。

本方案借鉴 RTC 的时序管理思想，不声称实现其条件生成算法。

## 9. 资源仲裁与交接

### 9.1 逻辑资源与物理输入

逻辑资源用于说明动作需求，后端将其映射为实际冲突：locomotion 与文本输入都可能写键盘，look 与槽位点击都可能写鼠标。不能只检查逻辑名称是否相同。

UI 模式使用共享 gameplay 租约和独占切换租约。独立观察可并行，转头观察需要视角权，打开背包需要 UI 切换权。

复合资源原子准入，原语不得拿着部分资源无限等待另一部分。后台任务不能通过高优先级自声明抢占身体。

### 9.2 优先级和公平性

生命周期异常与明确紧急停止优先；其次是必要的模式恢复、人类改向、当前任务和普通社交。普通控制台目标调整不等于必须在空中立刻切断全部控制。

长期饥饿由等待时间和阶段边界处理，但等待时间不会压过紧急身体恢复。持续无法回复聊天应产生可解释状态，而不是永久隐藏排队。

### 9.3 正常切换

REQUESTED → 新控制器检查能力 → 旧控制器进入受限 HANDOFF_PENDING → 到达交接区域 → 撤销旧租约 → 新鲜状态核对 → 授予新租约 → 首次输入验证。

受限旧控制器只能完成交接动作，不能启动新的挖掘或延长任务。交接超时转紧急流程。

### 9.4 紧急接管

原子撤销相关资源旧代次 → 恢复控制器取得新租约 → 根据实际模式维持身体 → 核对副作用与位置 → 进入稳定态或明确 CONTROL_LOST。

恢复控制器不存在适用能力时，不伪造安全保证。尽力停止危险持续输入，并向执行层报告无法保证保持姿态。

旧 finally 只能释放本实例仍持有的租约，不可调用全局 clearAllInputs 清除新 owner 的控制。全局释放只允许网关生命周期处理，且之后所有相关租约失效。

## 10. 进展检查

| 动作 | 合理进展 | 常见误判 |
|---|---|---|
| 导航 | 沿当前走廊推进、通过中间区域 | 绕障时到最终目标欧氏距离暂时增大不等于退步 |
| 跳跃 | 相位推进、落点误差变化 | 一直按 jump 不等于持续取得进展 |
| 游泳 | 垂直/水平目标推进、进入呼吸区域 | 水流导致位移不等于向目标推进 |
| 挖掘 | 合理持续时间内保持目标与工具条件，最终方块变化 | 动画或预计挖掘计时结束不等于成功 |
| 放置 | 交互请求与目标态核对 | 鼠标点击成功不等于方块出现 |
| UI | 进入正确界面、槽位状态改变 | 接受输入不等于焦点正确 |

进展检测使用滑动窗口、阶段期限和证据年龄。慢服务器与模型延迟分开记录；不能把所有超时统一归为 no_progress。

循环签名可包含目标、原语、局部区域、失败原因和关键前提摘要。相同签名在无新证据下重复超过预算时升级，不靠反复换 executionId 规避检测。

## 11. 恢复分类与状态机

```text
FAULT_OBSERVED
  → CLASSIFY_AND_SCOPE
  → CONTAIN_INPUT
  → STABILIZE_IF_POSSIBLE
  → REOBSERVE / RECONCILE
  → RETRY_LOCAL / REPLAN_SKILL / REPLAN_TASK / SUSPEND
```

分类可以不确定。恢复方案必须注明依据，避免猜测根因后直接大范围修改地图或知识。

| 异常 | 首要责任层 | 恢复与升级条件 |
|---|---|---|
| 小范围偏差 | Motor | 局部修正；超过控制范围才使动作失败 |
| 动态障碍 | 原语/局部导航 | 等待或绕行；预算耗尽才升级 |
| 相关几何失效 | Local Planner | 停止依赖该段的推进，重算受影响段 |
| 观测流缺口 | Bridge/World State | 使投影失效，恢复同步；不让模型猜缺失数据 |
| 位置修正 | State Estimator/Motor | 作废当前预测锚点，重建起始条件；不必抹除整个世界记忆 |
| UI 未知/焦点丢失 | 输入网关/执行器 | 撤销不安全输入，确认窗口与界面再继续 |
| 放置结果未知 | Effect Reconciler | 挂起相关依赖，核对目标与材料，不阻断无冲突避险 |
| API 不可用 | 模型调度器/技能 | 当前有效技能有限继续，到边界等待；不恢复过期动作 |
| 死亡/断线 | Session Runtime | 撤权、重新接入、检查点恢复，不重播按键 |
| 原语不支持当前地形 | Skill/Planner | 换原语或路线；不是“全世界不可达” |
| 反复同类失败 | Skill/Goal Manager | 冷却、换方案或求助，保留证据 |

恢复实例保存 parentExecutionId、failureSignature、budgetRef 和接管资源。原执行暂停时不能仍在后台续租。

## 12. 三个完整案例

### 12.1 导航时接到“回来”

控制台更新目标版本 → 当前导航停止扩展旧路线 → 若在地面可直接交接，若在跳跃则按受限合同完成落地 → 撤销旧导航资源 → 根据新位置规划返回 → 迟到的旧模型方案因目标版本不匹配被拒绝。

取消旧目标不删除已收集资源，也不把旧路线记忆判为错误。

### 12.2 从岸边落水

身体模式估计转 WATER → 地面前进不再满足原语前提 → 恢复实例接管移动资源 → 基于可得流体与支撑证据先寻找呼吸/保持状态 → 局部规划寻找可验证岸点 → exit_water → 地面状态核对 → 重规划原目标。

氧气字段缺失时记录限制；不能根据虚构剩余时间选择长潜水通道。若连头顶几何也未知，明确需要补充观测，不能保证所有水域都能自动脱困。

### 12.3 搭桥时服务器响应迟到

place_one 提交 → 本地动画出现但目标证据不足 → 进入 VERIFYING → 桥沿支撑控制保持 → 其他任务可推理但不能抢走支撑输入 → 方块被观察到后核对当前落脚 → 前移；若断线则 effect=ambiguous，重连后重新观察，不重复旧点击。

## 13. 调试、回放与验证

每个动作记录：目标、参数、原语版本、能力档案、观测引用、阶段变化、控制租约、输入摘要、结果证据与恢复关联。故障前后保留有界轨迹，不要求永久逐帧保存。

测试集合：

1. 状态机与资源性质测试：过期租约、重复命令、旧 finally、取消竞态。
2. 观测回放：相同证据序列产生可解释的阶段转换，不向真实身体外发。
3. 几何场景：半砖、楼梯、门、窄路、头顶障碍、水岸、梯子、桥沿。
4. 时序故障：延迟、队列积压、API 不可用、增量缺口、输入线程失效。
5. 多人变化：堵路、目标被先行破坏、材料/容器并发改变。
6. 长期恢复：反复失败预算、未决效果积压、控制权泄漏、资源饥饿。

指标包括动作条件下成功率、误放行不可执行边比例、进展误判、恢复成功率、接管延迟、过期命令拒绝和重复副作用。所有比例附条件与样本数。

原语晋升要求同时满足：执行能力、取消/交接、失败检测、证据完整性与回归测试。一次跑通不等于稳定能力。

## 14. 实现顺序与后续设计

依赖顺序：

1. 输入时效、资源映射与观测年龄合同。
2. orient_to、walk_corridor、UI 切换等最小可验证原语。
3. 局部动作图与导航进展检测。
4. jump、water、climb 的模式原语和交接。
5. dig/place 与副作用账本接入。
6. 组合技能、复杂地形、战斗扩展。

这是验证依赖，不是排期；身体接入条件未通过的原语保持不可用。

下一份文档细化持久化、知识/记忆/技能资产生命周期，以及目标与执行检查点的恢复事务。具体操作系统和客户端版本在接入原型开始前确定，不影响继续设计这些独立模块。
