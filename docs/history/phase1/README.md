# Minecraft Agent 第一大阶段开发交付包

交付日期：2026-10-17。用途：交给 Claude Code 或其他编码 Agent 实施，不是已开发完成的软件。

## 第一阶段目标

实现一个能够在**离线模拟客户端**上连续运行的 Agent Runtime：模型工具调用、结构化观测、目标与技能执行、输入仲裁、取消、结果核对、持久化恢复和控制台改向形成完整闭环。

同时实现 OpenAI Chat Completions 与 Anthropic Messages 的请求/响应适配器，通过本地 fixture/假 HTTP transport 验证；不要求真实 API Key 或付费调用。

真实身体目标仍是真实 Java 客户端、无客户端 Mod、无服务器改造、结构化优先、按需截图。**第一阶段的模拟后端是测试设施，不是把产品改成纯模拟器或 Mineflayer bot。** 无需真实 Minecraft 服务器，不要求启动本地服务端，不要求 GPU、游戏客户端或模型服务。

## 阅读顺序

1. `CLAUDE.md`：不可违反的约束与开发方式。
2. `IMPLEMENTATION_DECISIONS.md`：已固定的技术选型、数据表、模拟参数和处理规则。
3. `START_HERE.md`：可复制给开发 Agent 的任务提示词。
4. `PHASE1_SCOPE.md`：本阶段交付与排除项。
5. `TASKS.md`：按依赖执行的开发任务。
6. `CONTRACTS.md`：需要落实的关键接口语义。
7. `OFFLINE_ACCEPTANCE.md`：必须通过的离线验收。
8. `docs/`：三份目标架构文档。

## 预期使用方式

将此目录解压为新仓库根目录，在根目录启动 Claude Code，粘贴 START_HERE 中的提示词。开发 Agent 应直接实施本阶段，而不是继续产生一轮泛化设计或仅搭空目录。

若目标目录已有代码，先检查工作区与现有指令，保留用户改动；不得为套用目录模板而删除已有工程。

## 交付标准

完成后用户能在普通开发机器上安装依赖、构建、运行全部离线测试，启动模拟演示并通过控制台修改目标；进程退出后可以按持久状态恢复目标，但不会重放旧按键。

开发 Agent 必须提供 `DELIVERY_REPORT.md`，清楚区分：已实现、通过的离线测试、尚未验证的真实客户端/服务器行为。模板见同名文件。

资料中的目标版本、仓库能力和源码审计是研究输入，不代表已验证依赖。实际代码只依赖本阶段使用并锁定的包。

## 包含内容的边界

这是开发任务包，不含游戏文件、账号、密码、API Key，不包含已执行真实服务器测试的声明。三份设计完整保留；阶段约束与合同勘误以本包根目录文件为准。
