# 第一大阶段范围：离线可运行的 Runtime 基础闭环

## 必须交付

### 1. 工程与运行入口

完整 npm 工程、锁文件、严格类型检查、构建、单元/集成测试、示例配置、CLI 和开发文档。安装后无需游戏或 API Key 即可运行演示。

### 2. 合同与模拟身体

规范观测、快照、能力、执行、租约、输入与副作用 schema。实现确定性 FakeClientBridge：有界小地图、玩家状态、背包、UI 模式、聊天事件、移动和单次交互效果、可注入延迟/修正/断线/缺口。

模拟器只用于验证合同与编排，**不是 Minecraft 物理引擎**。不能用其跳跃或移动成功率支持真实控制能力。测试源明确标为 simulated，作用域与未来真实会话隔离。

### 3. World State

单写者归并、来源与时序、未知与冲突、会话/身体代次、不可变查询快照、相关依赖失效、序列缺口处理。实现 get_state、get_inventory、query_local_world 的精简投影。

### 4. 执行与控制

任务/执行/副作用独立身份；技能准入；控制租约；动作最后一跳校验；取消与有限交接；输入 TTL；重复命令保护；本地 watchdog；事件订阅与有界日志。

### 5. 可运行的最小技能

- `navigate_to`：在模拟已知小地图上进行 A* 与步行原语闭环；未知不可走，阻挡重规划且有预算。
- `observe_ui`：主动观察的执行合同，模拟打开/关闭界面。
- `send_chat`：UI 资源互斥、发送状态、无盲重发。
- `place_one`：模拟合法目标前提、意图持久化、效果核对与 unknown。
- `wait_for_condition`：有界等待，能取消且不阻塞其他任务。

跳跃/游泳/战斗只声明 unavailable 或提供明确的测试状态机夹具，不伪装成真实已完成原语。复杂建造、自动技能生成、完整知识系统不进入本阶段。

### 6. 模型与工具

统一模型消息、工具 schema 与结果；OpenAI Chat Completions 和 Anthropic Messages 的真实请求编码与响应解码代码，支持文本、图片引用、工具调用、流式工具参数拼接、取消和错误分类。

测试通过固定 fixture 和假 transport。提供 ScriptedModelProvider 支持确定性离线演示；它与两个生产适配器明确区分。

工具至少实现 get_state、get_inventory、query_local_world、capture_view、find_skills、start_skill、get_execution、cancel_execution、read_events、revise_goal、send_chat。capture_view 在 fake backend 返回标明 synthetic 的测试图片；真实后端不可用时返回 unavailable。不能把假图描述成真实游戏截图。

工具多轮循环可执行：事件/目标→模型→只读工具→模型→技能提案→异步反馈。执行无需等模型持续返回。独立只读工具可并行，写工具须准入。

### 7. 持久化与恢复

SQLite 保存目标、执行检查点、效果账本、关键事件和技能版本引用；迁移有版本。重启恢复目标与未决效果，拒绝旧租约，不重播输入。派生内存视图可重建。

Memory 本阶段只需结构化地点记录与经历事件存取、worldGeneration 隔离、失效标记；不做向量数据库、自动知识修正或大型 RAG。

### 8. 控制台与诊断

CLI 支持状态查看、设定/修改目标、暂停/继续、取消、发起聊天、查看执行与未决效果。测试和演示默认 simulated profile；真实 backend 配置在未实现时明确拒绝。

## 明确排除

真实服务器/真实客户端接入测试；OS 键鼠注入；真实协议代理；Minecraft 完整物理；新版协议猜测实现；验证码自动化；正版认证；训练；任意代码执行；完整建造与战斗；微服务平台；界面前端。

这些排除项属于后续能力，不意味着架构删除。第一阶段完成的准确名称是“离线 Runtime 基础闭环”，不能称为“真实服务器可用的完整 AI 玩家”。

## 完成定义

全部验收通过，模拟演示能够自主推进和接受控制台改向，重启与故障恢复真实走持久化/执行代码路径。真实后端未实现限制清晰，测试无网络与凭据需求。
