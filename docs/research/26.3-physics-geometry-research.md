# FurEverCraft — Minecraft Java 26.3 物理、碰撞几何与离线验证调研

> 研究范围：公开源码与结构化数据；未运行游戏、未连接服务器、未下载游戏 JAR 或资产。  
> 证据要求：区分 26.3 原版数据、第三方生成数据、跨版本继承数据和未验证算法。  
> 本报告整理此前已完成的源码阅读及静态 JSON 交叉检查结果；没有声称运行真实客户端测试。

## 1. 核心结论

- `RosegoldMC/minecraft-data.cr` 提供了明确针对 **Java 26.3** 的方块状态和静态碰撞形状表，适合作为 **候选几何数据**，但部分旧方块形状是按名称从 26.2 继承，并非全部从 26.3 运行时重新提取。
- 26.3 的 `mcmeta` `blocks/data.json` 与该项目的方块名称、状态属性在此前静态核对中一致：双方均有 **1286** 个方块，未发现名称或属性定义差异。此交叉核对**不能独立证明碰撞盒准确**。
- 固定快照下 `PrismarineJS/minecraft-data` 的 `dataPaths.json` 仅覆盖至 26.1，不能把 26.1 或 “latest” 冒充 26.3。
- `prismarine-physics` 是成熟的模拟算法候选，但 `lib/features.json` 对部分功能只列至 26.2；`26.3` 不能直接视作已支持。其默认物理常量不等于所有 26.3 玩家环境下的实际有效参数。
- 最小预测器应明确限制为 **已知、静态、普通地面上的站立玩家短程移动**；对液体、攀爬、动态碰撞、未知形状、过期状态返回 `UNSUPPORTED` 或 `UNKNOWN`。
- 规划器、Motor 和模拟身体若共享实现，不可互相证明正确。需要独立解析几何 Oracle、变形测试、异构实现差分、明确来源的轨迹以及未来真实 26.3 客户端录制。**差分一致不等于真实正确。**

### 2.1 RosegoldMC 实际静态检查

此前读取、解析并比较了 `data/26.2` 和 `data/26.3` 的 `blocks.json`、`blockCollisionShapes.json`：

| 指标 | 静态核对值 |
|---|---:|
| 26.3 方块名称数 | 1286 |
| 26.2 方块名称数 | 1196 |
| 26.3 新增方块名称数 | 90 |
| 26.3 最高 State ID | 35722 |
| 独立 Shape ID 数 | 334 |
| Shape 定义中 AABB 总数 | 732 |
| 找不到形状定义的引用 | 0 |
| 状态数与显式形状数组长度不匹配 | 0 |
| 状态属性笛卡尔积与 ID 范围不匹配 | 0 |
| AABB 中最小值 ≥ 最大值的错误 | 0 |
| 超出单方块 `[0,1]` 范围的 AABB | 113 |

**越界 AABB 不一定是坏数据**：围栏及部分特殊几何会扩展到所在单元格之外。空间查询不可假定所有形状均被 1×1×1 网格限制。

**数据来源的重要限制：** `tools/scripts/lib/collision.cr` 优先按方块名称继承旧版本形状；对于新增方块，再由 `tools/deltas/26.3.json` 中的 `collisionArchetype` 或 `collisionShapes` 提供形状。对 26.2 → 26.3 的既有 1196 个方块，形状映射未发生变化。这仅说明导出数据的继承关系，**不证明 26.3 游戏运行时的全部旧方块碰撞规则未变**。

生成器还通过 `tools/scripts/validate.cr` 检查模型解析及部分交叉文件一致性，但**通过结构验证不等于真实游戏物理验证**。

## 3. 必须分开的数据类别

| 类别 | 数据含义 | 推荐来源 | 常见误用 |
|---|---|---|---|
| 注册表／Block State | 方块名字、属性、State ID、默认状态 | `mcmeta` + RosegoldMC 26.3 | 把方块名字等同具体状态 |
| Collision Shape | 玩家或实体碰撞时使用的形状 | RosegoldMC 形状表 + 26.3 原版源码复核 | 将默认形状当成所有环境下的动态碰撞 |
| Selection / Interaction Shape | 鼠标选择、交互命中所用形状 | 需补独立 26.3 来源 | **把 selection 当 collision，或反过来** |
| 方块属性 | 硬度、挖掘条件、材料、表面行为 | 结构化数据 + 原版行为源码 | 用 `material` 字段推导全部摩擦／运动规则 |
| 运动物理 | 加速度、速度修正、重力、阻力、碰撞顺序 | 26.3 `LivingEntity` / `Player` 等源码 | 把旧版物理引擎常量直接标成 26.3 |
| 动态环境 | 液体、攀爬、活塞、粉雪、实体、反弹 | 相关行为源码 + 实测轨迹 | 静态 AABB 为空就当作空气 |

**雪层示例：** RosegoldMC 26.3 导出形状对 `layers=1..8` 依次为：空形状、0.125、0.25、0.375、0.5、0.625、0.75、0.875 高的盒体。此处是导出数据观察值，仍应由 26.3 原版行为或真实客户端验证。

**邻居与状态区分：** 对楼梯、围栏、墙而言，邻居通常通过服务端更新改变最终 Block State。若已拿到可信、及时的完整状态，不应无条件再次猜测连接关系；如果邻居发生变化且状态更新不完整，应标记过期或未知。

**默认形状表缺口：** 玩家姿态、实体碰撞上下文、移动活塞、流体、弹跳、攀爬、粉雪等并不一定能由 `stateId -> AABB[]` 唯一表示。

## 5. 物理参数：证据级别

`prismarine-physics` 当前快照 `package.json` 为 `1.11.1`。其 `index.js` 包含下列值；它们首先是**该库当前实现使用的值**，不可统一写成“26.3 原版参数”。

| 字段 | 库内值 | 适配判断 |
|---|---:|---|
| `gravity` | 0.08 | 26.3 源码有对应基本重力线索；有效重力受属性和环境影响 |
| `airdrag` | `Math.fround(0.98)` | 需要核对 26.3 空气阻力及属性运算顺序 |
| `playerSpeed` | 0.1 | 旧模拟参数，非直接输出的真实移动速度 |
| `sprintSpeed` | 0.3 | 旧模拟参数，需核对冲刺修正实现 |
| `stepHeight` | 0.6 | 默认候选，需核对 26.3 属性和跨越逻辑 |
| `playerHalfWidth` | 0.3 | 普通站立姿态候选 |
| `playerHeight` | 1.8 | 普通站立姿态候选 |
| `defaultSlipperiness` | 0.6 | 不适用于所有地面材质 |
| `airborneInertia` | 0.91 | 需核对有效摩擦和更新顺序 |
| `airborneAcceleration` | 0.02 | 未完成独立 26.3 全条件验证 |
| `waterInertia` | 0.8 | 不代表完整流体动力学 |
| `lavaInertia` | 0.5 | 不代表完整流体动力学 |
| `liquidAcceleration` | 0.02 | 流体特性仍需补全 |

公开 26.3 `LivingEntity` 源码视图：[mc-packet-reference（第三方）](https://mc-packet-reference.netlify.app/26.x/source/net/minecraft/world/entity/livingentity/)。重点进一步核查 `travelInAir`、`travelInFluid`、`travelInWater`、`getJumpPower`、`jumpFromGround`，以及 `FRICTION_MODIFIER`、`AIR_DRAG_MODIFIER`、`JUMP_STRENGTH` 等属性。第三方源码网页不能取代正式运行时测试。

**直接适配阻塞：** `prismarine-physics/lib/features.json` 的 `proportionalLiquidGravity` 版本列表包括 `26.1` 和 `26.2`，但不包括 `26.3`；`index.js` 会依据 `mcData.version.majorVersion` 选取特性，缺失适用的液体重力分支可能抛出 `No liquid gravity settings`。此外，`getSurroundingBBs()` 在 `world.getBlock()` 为 `null` 时跳过对应碰撞形状；FurEverCraft 不能让“未观测区块”默认为“空气”。

**额外版本风险：** Java 26.3 发布周期包含台阶跨越碰撞问题 MC-310289 的修复。几何形状相同不意味着旧跨越算法正确：[Java 26.3 Pre-release 1 官方说明](https://feedback.minecraft.net/hc/en-us/articles/48576647862669-Minecraft-Java-Edition-26-3-Pre-release-1)。

## 6. 26.3 覆盖／缺口矩阵

| 模块 | 当前证据 | 能否批准安全移动 | 绕开方法／补证据条件 |
|---|---|---|---|
| 方块名称／状态属性 | 两套 26.3 数据交叉一致 | 可作为候选正式映射 | 固定版本、检测非法 State ID |
| 数字 State ID | 26.3 报告衍生数据 | 有条件 | 结合实际协议观测再验证 |
| 普通静态实心 AABB | 26.3 数据；旧版继承 | 有条件 | 白名单、独立几何 Oracle |
| 半砖／楼梯 | 有完整状态形状表 | 暂不自动批准复杂动作 | 完成独立几何和跨越测试 |
| 围栏／墙 | AABB 可能高于格子或跨格 | 暂不批准跨越 | 越格空间索引、几何测试 |
| 门／活板门 | 状态定义齐备，但动态变动 | 限定通行 | 动作前确认最新状态 |
| 雪层 | 导出碰撞数据齐备 | 限定支持 | 独立核对雪层接触／支撑 |
| 玩家姿态／属性 | 旧版候选，部分源码线索 | 仅站立普通玩家 | 核对 26.3 `Player` 属性和尺寸 |
| 普通水平运动 | 有旧版算法和 26.3 源码线索 | 极短窗口、有条件 | 输入采样／速度状态核对 |
| 冲刺／跳跃 | 规则分支不完整 | 不用于危险动作 | 源码核对＋轨迹验证 |
| 台阶跨越 | 26.3 专门修复过相关碰撞 | 不用于精确保证 | 独立核对跨越算法 |
| 下落 | 重力证据存在，但落地过程未完整验证 | 仅做危险识别 | 完整 tick 顺序和接触检查 |
| 水／熔岩／气泡柱 | 缺动态模型 | **不批准** | 另行引入流体模型 |
| 攀爬／脚手架 | 默认几何不足 | **不批准** | 明确 `CollisionContext` 等规则 |
| 活塞／粉雪／蛛网／弹跳 | 动态和上下文相关 | **不批准** | 专门模型和轨迹 |
| Selection / Interaction Shape | 没有完整核实的 26.3 表 | **不批准精确交互** | 独立形状数据和源码证据 |
| 位置修正／世界状态过期 | 可以定义拒绝语义 | 旧预测立即失效 | 未来客户端＋协议联合验证 |

## 7. 推荐的最小预测器

目标不是完整复刻 Minecraft，而是在保守能力边界内回答：“下一段极短的输入是否有可确认的几何阻挡或明显运动风险？”

```ts
// 仅为接口边界示意，不代表已实现。
type PredictRequest = {
  version: '26.3';
  protocolVersion: 777;
  connectionEpoch: number;
  bodyEpoch: number;
  worldRevision: number;
  observationTime: number;
  player: {
    position: Vec3;
    velocity: Vec3 | { kind: 'unknown' };
    yaw: number;
    pose: 'standing' | 'other';
    onGround: boolean | 'unknown';
    attributes: Record<string, number> | 'unknown';
  };
  world: LocalWorldSnapshot;
  input: KeyInput;
  horizonTicks: number;
};

type PredictResult =
  | { status: 'SUPPORTED_CONDITIONAL'; state: PredictedState; uncertainty: UncertaintyEnvelope; evidenceIds: string[] }
  | { status: 'UNKNOWN'; reason: string }
  | { status: 'UNSUPPORTED'; feature: string; reason: string };
```

严格区分：

- **KNOWN_AIR**：已经观测到的空气，可用于判断自由空间。
- **KNOWN_BLOCK**：已经观测到且当前版本形状已验证的状态。
- **UNKNOWN**：未载入、过期、不同维度／世界 epoch、缺状态 ID 或缺可靠形状。

不能把 `UNKNOWN` 当空气，也不能把它当“可靠实心支撑”。把未知当完整方块可用于**阻止批准通行**，但绝不能用来证明脚下有地面。

第一阶段仅准入：普通站立、已知静态干燥地面、可确认速度／运动属性、无外部力或特殊效果、无液体、无动态实体影响的短程平地动作。支持 AABB 裁剪、普通碰墙、头顶净空、地面支撑、短程运动候选及失效检测。

## 8. 防止循环证明的离线验证方案

| 验证方式 | 独立性要求 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 状态数据交叉核对 | `mcmeta` 与 RosegoldMC 独立读入、比较状态 | 名称、属性和值域一致 | 完整碰撞形状和动态物理正确 |
| 手工解析几何 Oracle | **不调用生产预测器或其碰撞辅助函数** | AABB、扫掠、支撑、越界及边界几何 | 原版完整运动规则 |
| 独立实现差分 | 预测器和参考实现不能共享运动核心 | 发现实现分歧、回归 | 两者一致不等于原版正确 |
| 变形测试 | 预先定义不变量 | 平移、旋转、负坐标、已知静态障碍一致性 | 特殊动态行为正确 |
| 公开来源明确的 26.3 轨迹 | 固定游戏版本、输入、状态、tick | 特定场景的真实运动验证 | 所有服务器与客户端情况 |
| 未来真实客户端录制 | 客户端观测独立于模型输出 | 真实误差、延迟和位置修正行为 | 未覆盖场景的绝对正确 |

**示例：** 半宽 0.3 的玩家向 `x=1` 的完整方块墙移动，中心理论上不能超出 `x=0.7`。这由独立几何推导给出，不需要调用 `prismarine-physics`，适合作为 Oracle。

一旦生产预测器与测试模拟身体使用相同 `stateId -> AABB` 表，两者一致只能说明它们消费相同数据、执行相同数学；要验证数据本身，需第三方原版源码／独立导出或未来真实客户端场景。真实客户端轨迹集截至本次研究**未完成可靠核实**，不应编造。

## 9. 分阶段支持范围

| 阶段 | 准入地形／动作 | 必须返回 UNKNOWN / UNSUPPORTED | 开放下一阶段条件 |
|---|---|---|---|
| P0：静态数据接入 | 26.3 状态查询、形状解析、AABB 算法 | 非法／缺失 State ID，缺区块，形状不可解析 | 独立数据结构核对通过 |
| P1：普通平地 | 已知干燥完整方块、普通站立、短程行走、碰墙 | 悬崖风险、复杂形状、跳跃、冲刺危险落点、液体、动态环境 | 基础运动源码核查、Oracle 通过 |
| P2：复杂静态几何 | 半砖、楼梯、雪层、墙、围栏、可确认状态的门 | 未确认邻居状态、含水互动、动态状态 | 分状态碰撞及跨越测试通过 |
| P3：增强运动 | 冲刺、跳跃、下落、空中控制、姿态 | 缺有效属性、缺输入采样证据 | 26.3 源码核对＋异构差分 |
| P4：动态物理／客户端验证 | 液体、攀爬、特殊块、移动碰撞、真实闭环 | 未覆盖外力／特殊上下文 | 原版 26.3 轨迹实测与误差上界 |

任何阶段都必须在世界 epoch、连接 epoch、观测 revision 或位置修正导致前提失效时撤销旧预测。

## 12. 最终取舍

采用 **mcmeta 26.3 + RosegoldMC 26.3 静态数据** 建立版本化方块／形状资产；把 `prismarine-block` 的 State→Shape 适配和 `prismarine-physics` 的运动实现作为**参考与差分对象**，而不是直接当成 Java 26.3 真实物理引擎。

FurEverCraft 的独立局部预测器首期只覆盖可信静态地形、普通站立玩家、短程移动与明确几何碰撞；所有不具备必要状态或行为证据的场景都必须报告不支持或未知。

**核心验证原则：用 26.3 数据确认状态与几何，用独立解析案例检查数学实现，用 26.3 源码确认运动规则，再通过未来真实客户端轨迹确认最终误差。四者不能互相替代。**
