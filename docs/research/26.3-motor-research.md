# FurEverCraft / Minecraft Java 26.3 闭环 Motor 与 Windows 输入研究

**研究日期**：2026-10-18  
**代码基线**：`THEWOLFWALKER/FurEverCraft` `main@7be88288cd8690096bf056c446153ab5a4319859`（提交时间 2026-10-18T05:29:45Z）  
**范围**：纯原版客户端、Windows 10/11、被动观测、OS 键鼠、离线研究。未运行 Minecraft、未调用真实 SendInput、未截图、未连接服务器、未下载游戏 JAR/资产。  
**证据语义**：**V**=核实（公开官方文档/当前仓库源码）；**I**=合理推断/推荐工程方案；**U**=26.3 真实客户端实测未验证。`V` 不意味着已经证明“真实游戏中可工作”。

## 0. 核心结论

1. **V：Java 26.3 已由 GLFW 切换为 SDL3**，物理键绑定采用 SDL scancode，游戏中鼠标始终使用相对模式；旧 GLFW mouse-to-yaw 经验不能视为 26.3 适配成功。官方发布说明明确如此。[E1]
2. **V：Win32 SendInput 可将输入事件插入 OS 输入流，但不保证 SDL3 的游戏进程实际接收/消费。**SDL3 的 Windows 后端存在 Raw Input 分支，`WM_INPUT` 与传统 `WM_MOUSEMOVE` 并非同一机制。特别是 `SendInput(MOUSEEVENTF_MOVE)` 能否进入当前 26.3 游戏所走的相对鼠标路径，**U**。不宣称一定失败，也不宣称已兼容。[E3][E4][E5]
3. **I：Motor 首选“有限状态机 + 有限时段前馈 + 位置/姿态反馈 + 风险监督器”**；转向用分段比例控制/死区与速度限制，位移用分段速度与可停距离；PID 仅作为可选低阶子控制，MPC 仅在模型可靠后按实际失败案例引入。
4. **V：现仓库不是已验证的实时闭环。**当前 `BoundedObserver` 明确只产出帧元数据，没有 26.3 运动字段；`BodyReader` 来源限定 `simulated`；`Motor.send()` 将网关 `accepted` 立即升级成 `succeeded`，读取新 `pose` 并不能证明发生过游戏 tick 或服务器接纳。[R1][R2][R3]
5. **V：现有独立 helper 的 watchdog 并非在 helper 中独立计时释放。**PowerShell `ReadLine()` 阻塞时不会主动检查其 `heartbeatDeadline`；Node 驱动的 `setInterval()` 必须活着并能向 helper 发送释放命令。应将“输入寿命到期即释放”落实到 OS helper 自身、与父进程无关的定时机制；此项是投入真实控制前的阻断条件。[R4][R5]
6. **I：闭环的输出是状态/事实，不是调用回执。**分离 `OS_SUBMITTED`、`CLIENT_OBSERVED`、`SERVER_RECONCILED`、`GOAL_VERIFIED` 等证据级别，不能伪造缺失的服务器逐步确认。

## 2. 可观测状态：协议世界与物理世界分离

### 2.1 候选来源与证据等级

| 字段 | 客户端→服务器流 | 服务器→客户端流 | 闭环应该如何处理 |
|---|---|---|---|
| 自身 x/y/z 与 yaw/pitch | 在成功建立对应 26.3 movement packet 解码后，可以取得客户端**报告值**（字段/发送条件须针对 26.3 schema 验证） | 某些位置同步、传送、重定位消息可提供服务器主动下发的新锚点；**并非每个本地位置包都有逐包确认** | `CLIENT_REPORTED` 与 `SERVER_CORRECTION` 独立储存 |
| 自身速度 | 不能仅由位置包直接得到权威逐 tick 速度；差分仅为估计 | 速度、推力等相关事件可能局部提供约束，字段及自玩家适用性须验证 | 估计 `velocity`+区间/方差，标记估计器版本 |
| 是否落地 | 若对应运动包有 ground 标志，代表客户端声称；其他碰墙标志同理需核字段 | 服务端可纠正但无持续“落地确认”通道 | `reportedGround` ≠ 真实接触；结合几何/轨迹保持不确定性 |
| 碰撞接触面 / 距障碍 | 无直接连续碰撞法线或完整 contact manifold | 区块 block state/实体数据可支持几何推断，前提是碰撞形状与覆盖率已验证 | `CLEAR / BLOCKED / UNKNOWN / UNSUPPORTED`，禁止 UNKNOWN 当 AIR |
| 自身视线命中的精确 block face | 单靠本机移动包不直接报告本机准星命中结果 | 方块更新/交互结果能作为间接证据 | 几何 raycast 是 `PREDICTED_HIT`，最终 effect 按世界更新核对 |
| gameplay / chat / inventory / pause UI | 不存在可以普遍代替本机 UI 实际状态的标准运动字段 | `open_screen` 一类消息只能覆盖服务端开启的 UI；玩家本地 ESC、聊天输入等不能保证可见 | 单独的 `UiModeEstimator`；不确定时禁止游戏动作/文本错路 |
| 焦点/窗口/PID/HWND | 无 | 无 | Windows helper 探测，不能从协议推出 |

**数据链**：`Forwarded frame` → `Versioned decode` → `SourceStampedEvent` → `StateEstimator` → `LocalControlView`。当前仓库真实 observer 还处于 `frame-metadata` 层，不能将这个链条当作已实现。[R3][R6]

### 2.2 时间戳及推断原则

每条输入/观测至少记录：`connectionEpoch, bodyEpoch, dimension, observerEpoch, direction, streamSeq, packetKind, adapterVersion, receiveMonoTs, decodeMonoTs, maybeClientTick, maybeServerTick, source, confidence, observedFields, gapStatus`。

- `receiveMonoTs` = observer 本地收到字节的单调时钟；**不是**客户端模拟 tick 或服务器 tick。
- `clientReportedPose` = 客户端发送时的观测/预测轨迹结果，传输延时不可忽略。
- `serverCorrection` = 服务器对位置/朝向的主动重定位信号，必须立即成为新位置锚点并使旧预测失效，但**无重定位不构成每次动作已获服务器确认**。
- `poseEstimate(now)` = 上一个观测加本地动作与运动估计滚动得到的临时估计，附 `ageMs`、`uncertainty`、`assumptions`，不得改写成 observed。
- `duration ≈ ΔreceiveTs` **不能**当作经过了整数 `clientTick`；可以在已核验的发送速率/RTT 分布下做不确定时间窗估算，始终保留界限。
- 若相关区域/协议域出现 `observer_gap`，仅降级受影响字段；若 Play framing/压缩/协议 epoch 无法识别导致全局失效，阻断全部新的依赖闭环的动作。

### 2.3 估计器的年龄分级——设计候选而非 26.3 实测常数

对**正在移动**的玩家，建议初始策略：`age ≤ 100 ms` 允许小幅反馈；`100–200 ms` 限幅并只执行已证明安全的短时段；`>200 ms` / 连续数个预计运动报告缺失 / 观测 epoch 改变，则撤新输入并进入 `OBSERVATION_STALE`。这些毫秒数是离线压测起点，不是Minecraft保证的发包周期。**静止时没有位姿更新不应直接判为异常**；只有正在期望位移且明确定义有应到事件/心跳语义，才能用超时诊断。

不依赖单一阈值：对高风险边缘/跳跃，要求位置新鲜、低不确定性、支持面已知；安全平地可允许较长时段，但只能以动作安全包络为依据。把 `Δpos / Δt` 估速与缺报、服务器回正区分；近零差分不能在无新观察时误判卡住。

## 3. 控制方法比较与取舍

| 方法 | 依赖/成本 | 鲁棒性 | 26.3 适用结论 |
|---|---|---|---|
| 离散 FSM + 规则 | 无精确模型；极低 CPU | 恢复和模式门禁好；纯开环精度差 | **必须作为上层原语状态机** |
| 前馈 + 观测反馈 | 简单局部时长/速度关系；低成本 | 对延迟、低质量速度模型较稳健 | **第一选择**：脉冲短动作+重估；限制最大时间/距离 |
| P / PI / PID | 连续量测与采样时刻，处理饱和、防积分饱和；低成本 | yaw 小误差可使用 P；地面移动用长积分易在离散按键/碰撞引发超调 | **角度轴仅可选 P/PD**；PID 非默认 |
| 有限短时轨迹跟踪 | 地形/速度上界、可停性；低至中成本 | 有安全走廊时有效；静态轨迹必须可中断 | **第二层能力**：每 1–3 控制帧重算，不死播 |
| Sampling / MPC | 已验证离散物理、时延、动作-观测模型；中至高成本 | 遇动力学失配和错误碰撞比简单控制更脆弱 | **暂不选**；仅有高频测量与实测收益才增量试点 |

**建议控制式（概念）**：

- 水平目标相对方位：`θ_target = atan2(-dx, dz)`（需校验项目坐标与左右手约定）；误差：`wrapTo180(θ_target − yawEstimated)`；输出按比例限幅为**期望 yaw 角变化**，再通过已校准的鼠标脉冲实现；**不要**把 `Δyaw` 整数硬塞进 `moveRelative(dx)`。
- 前进/横移：把世界坐标误差旋转至玩家机体坐标；离散按键取 `heldSet`，短时预测 `d_stop ≈ max(0, v_parallel) × (τ_act + τ_obs + τ_release) + d_coast + margin`。这里 `v_parallel`、尾程惯性和延时必须来自实测/有界模型；下不了界就只允许更短的安全平地动作。
- 控制优先级：`focus/lease/epoch` > `UI exclusion` > `geometry risk` > `stale observation/correction` > `primitive controller` > `OS input`。安全优先于轨迹误差。
- 多种运动模式（行走/冲刺/潜行、跳跃、下落、游泳、攀爬）分 profile，不让陆地的标定复用到空中和水里。

## 4. Motor 模块边界与合同

```
Planner/Skill ──目标 + 约束 + owner + 可接受风险──> Motor Primitive Executor
                                       ├─ LocalControlView (只读、带 epoch/age/confidence)
                                       ├─ SafetyEnvelope / UiModeGate
                                       ├─ FSM Controller / StateEstimator / CalibrationProfile
                                       ├─ Progress & Correction Detector
                                       └─ InputIntent (短期、幂等 held-set / 非幂等相对增量)
                                                   ↓
                                        Existing Input Arbiter (唯一实际写入口)
                                                   ↓
                                         Windows Helper / watchdog
                                                   ↓
                                         普通原版 Java 客户端
                         observer(只读) ────────→ LocalControlView
```

建议保留 Runtime 的 `owner/generation/lease/connectionEpoch/bodyEpoch`，**不建立第二个控制入口**。新增 Motor 局部对象：

`MotorCommand { primitiveId, goalId, ownerToken, generation, context, target, horizon, mode, preconditions, safetyEnvelope, sourceObservation }`

`MotorView { context, poseClient, poseServerAnchor?, velocityEstimate?, groundedClient?, blockGeometryRefs, uiMode, focus, calibrationId, lastEventTs, observationAge, uncertainties, gaps }`

`MotorPulse { context, ownerToken, generation, parentPrimitiveId, observedRevision, generatedMonoTs, expiresMonoTs, heldSet, mouseDelta?, reason, maxExpectedDisplacement }`

`MotorFeedback { primitiveId, phase, lastEvidenceRef, elapsed, positionError, angleError, progress, controlReceipt, completionEvidence, status, errorClass, certainty }`

**五种性质必须分开**：`intent accepted` / `helper OS posted` / `client pose moved` / `server response reconciled` / `task actually satisfied`。未收到更强证据不能凭逻辑推理提升确定性。

FSM 共有状态：`CHECK → ACQUIRE → ACT → OBSERVE → VERIFY → SETTLE → SUCCEEDED`；异常路径 `CANCELING → RELEASE → VERIFY_RELEASE → CANCELED/CONTROL_LOST`；`PRECONDITION_UNKNOWN` 不进入 `ACT`。

### 4.1 按键与 UI 的互斥语义

`MOTION`、`AIM_AND_USE`、`GUI`、`CHAT` 是互斥**输入模式**，不是按键级小锁。转换时先提交 `heldSet={}`，再经过短确认/观测窗；切到 GUI/CHAT 必须禁止 look/move/jump/attack/placement，切回 MOTION 时先验证 UI 已关，不能只假设 Escape 成功。不同动作可以拥有相同 `executionId`，但绝不可同时持有两套可以改写相同物理输入的 owner。

`setHeldInputs` = 用整个期望 held set 替换旧 held set；不会因同一个 owner 的两个相邻运动脉冲释放/再按而产生无意义抖动。临时跳跃需要边沿（按下/释放）和最短状态时间约束，不能每轮将 jump=true 解释为新的独立跳跃。非幂等相对鼠标/点击/打字在超时响应丢失后只核对后续事实，绝不补发同样的物理位移。

## 5. 六类最小运动/交互原语规范

下述超时为设计上的阶段预算候选，应由延时/轨迹分布与风险 profile 标定，不是游戏固有常数。无新鲜观察或抢占时第一步都必须**尽力释放原 owner 的 held set**，随后标记控制确定性（可能不可证）。

| 原语 | 必要前提和输入 | 闭环动作 | 完成判据（不是 SendInput 回执） | 超时和失效 | 恢复 |
|---|---|---|---|---|---|
| `turn_to(yaw,pitch)` | gameplay、焦点真、校准可用、最近姿态可信；yaw/pitch 目标 | 包裹角误差，分段鼠标脉冲，限制单脉冲像素/角度；有回报才发下轮 | 连续 2 次新姿态在角误差容差内，且观察不再显示继续转动 | 每脉冲短期到期；阶段最多约 1–3 秒（候选）；姿态突变/无角响应/边界夹角 | 释放所有非必需按键，归零预测，重读校准/姿态，有限小脉冲重试 |
| `approach(target,safeRadius)` | 目标周边可站立，已知支撑面、无危险碰撞；地面 profile | 先对正，再沿保守短段前进；跟踪世界误差、横向误差和停止余量，近目标降速 | `distance ≤ tolerance` 且速度估计/连续位移小到可驻留至少两个新观察 | 阶段由距离上限+观测龄推算；偏航、横向漂移、阻挡、回正、风险突然升高 | 松键、稳定后局部重定向或申请新局部路径，有限试次 |
| `stop_and_settle` | 能确定 owner/lease（即使姿态不可信仍可执行释放） | 原子替换空 held set；取消待发非幂等鼠标；观测惯性/位置变化 | `inputs released at helper` 与 `physical stable` **分别记录**；缺运动证据仅能报告释放尝试 | 释放超时或 helper 不回应归类 `CONTROL_LOST`；持续滑行不算停止 | helper 侧定时 release、fence 旧 generation、在物理可信后再开始其他原语 |
| `jump_short(landing)` | 高置信起跳支撑、落脚面/头顶净空/水平走廊、死亡/坠落风险包络已知 | 调整起跳方向→短跳输入→按约束修正水平推进→落地前停输入/保持安全方向 | 新鲜姿态显示经过上升/下降相位，落点在支持面上，若 `onGround` 仅客户端报告则低于完全确认 | 预算包括起跳、空中、落地；无支持、修正、未知障碍、轨迹出安全域立即失效 | 空中若没有合格空中恢复 profile，不猜测救援；撤新输入并上报，落地后重建 |
| `edge_approach(target,margin)` | **已知**边界/实体碰撞/支撑面；潜行绑定已验证；可停距+不确定性+余量 < 可用支持区宽度 | 禁冲刺；短脉冲，随边缘距离递减脉冲，观测收敛 | 站稳于边缘**内侧安全点**，速度低于阈值；绝不以到视觉边为目标 | 支撑未知、观察超龄、可停距超预算，立即冻结边缘推进 | 停稳并后退到安全支撑区（只有后退走廊已知且姿态新鲜才可执行） |
| `aim_and_dig/place(targetFace)` | gameplay/焦点、视点姿态与局部 block state 可用、工具/物品/交互距离/权限前提成立；交互由 Skill 决定 | 几何选候选射线→小脉冲校准瞄准→短 press/release 或可取消的持续按住→观察世界/库存变更 | 命中朝向置信够 + 相应方块状态变化/库存或进度证据；不能用“点击成功”判断完成 | 目标消失、方块/实体遮挡变化、错误 UI、未确认副作用、超时 | 停点击/按住；查询新方块状态与 effect ledger，无法归因时返回 `AMBIGUOUS`，不自动补一次放置 |

重要限制：挖掘与放置的动作时序不仅依赖 mouse click；挖掘可要求持续 `attack`，服务器会验证工具、视线、方块和时间等。具体原版 26.3 交互公式、形状、点击重复率没有从真实 26.3 原版源码/客户端验证，当前只能把动作时序作为候选。

## 6. Windows 输入工程与校准

### 6.1 目标窗口

绑定 `HWND + PID + 可识别进程生命周期`；`GetForegroundWindow()` 和 `GetWindowThreadProcessId()` 可核验当前聚焦身份。`SetForegroundWindow` 受 Windows 激活策略限制，不能强夺焦点；**推荐焦点不符直接禁止新动作**，而不是自动切换焦点。窗口标题不能作为唯一标识；HWND 重用、进程退出、桌面切换、最小化、切分屏、后台窗口、有 modal 菜单均令控制失效。[E6]

输入是系统输入流操作，不是“定向发给 HWND 的私有事件”。即便 `SendInput` 返回 1，也必须分别检查 OS API 回执与游戏状态。不用 `PostMessage`/伪造 `WM_INPUT`/游戏内存或客户端 Mod 绕过限制。

### 6.2 Keyboard：Windows VK vs 扫描码 vs SDL scancode

Windows `KEYBDINPUT.wVk` 与 `wScan` 为两个不同标识空间。`KEYEVENTF_SCANCODE` 使用硬件扫描码，`KEYEVENTF_EXTENDEDKEY` 处理扩展键；SDL3 `SDL_Scancode` 是 USB usage 层编号（如 W 是 26），**绝不能直接把 26 当 Win32 VK 或硬件扫描码**。建议由绑定 `physicalAction → Win32 scan+extended+layout → expected SDL scancode` 的显式 profile 驱动。[E1][E7]

当前 helper 的 `Key()` 在 `wVk=code`、`dwFlags=0/KEYEVENTF_KEYUP` 发送 VK，这种实现可能在 US QWERTY/默认键绑定中貌似工作，但无法据此宣称适配了 26.3 物理位置语义。[R4]

### 6.3 Mouse：相对位移与灵敏度

`MOUSEEVENTF_MOVE` 的 `dx/dy` 为 Windows 相对鼠标数据，微软文档说明会受 OS 鼠标速度/阈值加速影响；SDL3 的原生 relative mode 报告相对移动，可能采用 Windows Raw Input 路径，不能假设上述位移 1:1 进入 SDL mouse motion。[E4][E5]

**未来真实客户端校准（本轮不执行）**：

1. 确认 Minecraft 26.3 与实际的 SDL/Windows 客户端构建、OS、显示器、DPI、鼠标设置、游戏灵敏度、游戏/GUI 模式；先冻结配置。
2. 要有可靠 yaw/pitch **客户端移动包观测**；在稳定无转动状态输入**极小**正、负 dx/dy 脉冲，等待独立新姿态读数，比较观察前后差异。没有可靠姿态就不能输出“校准成功”。
3. 分别拟合两个轴、正负方向、不同幅度与不同停顿的 `angle change / requested counts`，取中位数和分位范围；使用多点非线性拟合而非预置 `0.6^3 × 8` 等旧版经验常数。小样本/线性不足不得扩大工作域。
4. 检查持续小脉冲对 yaw/pitch 的单调性、量化阶梯、轴符号、极限夹角、原点附近死区、灵敏度改变、GUI 进入/退出、焦点切换和远程桌面等边界。
5. 仅当多个无冲突样本证明实际客户端响应后将 `relativeMouseMotion` 的能力从 `unverified` 升为受条件限制的 `experimental`；更多硬件/场景回归才可 `enabled`。

记录 `gainX±/gainY±`、噪声/量化、非线性区、配置指纹、样本数和置信界。yaw 使用环形差；pitch 接近 ±90° 时不要用线性增量无界外推。窗口 DPI/分辨率最直接影响光标绝对坐标与 GUI 定位；它是否影响游戏 relative mouse 的角度增益须以校准数据为准，不能笼统认定一定同比例变化。[E8]

### 6.4 helper 的生命期和多层收据

- `CommandReceipt`: request 已被 helper 接收/校验；`InputDispatchReceipt`: OS `SendInput` 返回项数；`BehaviorEvidence`: 客户端姿态/服务端事件；`Outcome`: 任务实际达成。
- `setHeldInputs` 是希望的完整集合；helper 保存**自身已实际按下**的键，与父进程逻辑状态独立；按键/鼠标各自拥有释放跟踪。
- `requestId` 用于 IPC 请求去重，`commandId` 用于副作用去重；**helper 重启时进程内 `seen` 清空**，因此不重播旧 click/text/mouse 操作。helper 新启动必须新 helper epoch，与旧 lease 不可兼容。
- `generation` 必须在**所有**输入命令都 enforce，且应由绑定到该 helper 实例的 owner identity 和 profile fencing 驱动；按代次拒绝旧结果。
- `leaseUntil` 当前跨 Node `performance.now()`（单调）和 helper `[DateTimeOffset]::FromUnixTimeMilliseconds`（Unix wall clock）**时钟域不兼容**，如果上层沿用 SystemClock 直接赋值将误过期。需要明确跨进程映射+不确定度或由 helper 签发本地相对 TTL；不能“到达后再刷新过期时间”。[R7][R4]

## 7. Tick、时钟、固定周期和事件驱动

- Minecraft 模拟通常以 20 tick/s 为常识性候选，**不能据此宣称网络每 50 ms 出包**、游戏渲染每 50 ms 运行、或 Node helper 每 50 ms 响应。
- 采样源独立：`game tick`/`server tick`、`movement packet events`、`observer receive time`、`Motor control deadline`、`OS helper watchdog deadline`。
- Motor 使用**事件唤醒 + 约 20 Hz 软实时兜底**：到达新姿态、新纠正、窗口焦点变更、目标变化、取消、观察 gap 时立刻重估；定时周期保证最大无事件检查间隔，但每轮计算真实 `now` 和 jitter，不能用固定 `dt=0.05` 冒充。
- 错过周期**不追帧补发**，只执行最新目标状态；观测陈旧则先释放。执行时间、事件队列长度、过期输出比例纳入 telemetry。
- Planner/大模型可以卡住但不得阻塞 Motor；Motor 自身进程或 Node event loop 也可能卡住，因此 release 必须由 helper 里独立的 watchdog 完成。OS 进程被挂起、整机休眠等更严重场景不能承诺零迟延，需标注剩余风险。

**致命点（已核实代码）**：`FurEverCraft.Helper.ps1:34,47-53,77` 将 `heartbeatDeadline` 设为 8 秒并仅在收到下一条请求的 `Assert-Action` 检查；`while (ReadLine())` 无异步计时任务；`driver.ts:92-95` 的 Node watchdog 通过 transport **异步**发送 release 命令。如果 Node 事件循环完全卡住且 helper stdin 尚未 EOF，长按无法靠 helper 自身在 8 秒到期时清除。这与“独立 helper 保证过期输入释放”的合同尚不匹配。[R4][R5]

**可验证的较强合同**：helper 独立、单调计时驱动下一次过期事件；任何 held 按键有 helper 侧绝对或相对上限；心跳不能仅重置不可信旧 owner 的输入寿命；持有输入不能跨 `bodyEpoch`、`helperEpoch`、`focusEpoch`；若不能确认物理释放，报告 `RELEASE_UNCERTAIN`，直到重新绑定/观察事实。

另一个明显的**源码语义风险**：`src/fixtures/simulated-body.ts:34-38` 先记录 `input=active.at(-1)`，过滤已过期条目之后又以 `active.at(-1) ?? input` 回退；因此即使所有条目已过期，**本轮 tick 仍可能用刚被清理的旧输入执行一步**。这是假身体测试的重要例子，不应让 fixture 自己掩盖 release 问题。

## 9. 离线验证：FakeHelperTransport / 录制轨迹 / 时延模型

### 9.1 测试装置，不接真实客户端

1. `FakeHelperTransport` 决定 helper 拒绝、重复确认、超时、乱序回应、丢回应、helper 崩溃/重启、focus flip；模拟 IPC 不假设 OS 有输入。
2. `SyntheticSDLConsumer` 是**明确标记为假设**的接口：可配置“接收 VK 不接收 scan”、“mouse received=0”、“mouse gain+noise”、“UI 接收但 gameplay 未接收”等。它不是原版SDL；只能用于验证状态机面对适配失败时是否安全。
3. `SimulatedBody` 使用受约束的多套物理近似及误差包络：地面加速、减速、摩擦、碰撞、滞后、跳跃、落地等；参数分布与原版不绑定，至少有一套 adversarial fixture 能揭示固定速度假设失效。
4. `TraceReplayer` 保留 timestamp 和双向事件顺序，不依赖 wall clock；注入网络分段、协议 gap、分域失效、带宽排队、服务器 correction，使用独立 fake monotonic clocks。
5. 明确 `proofScope=synthetic_contract`；不能根据同一个近似预测器生成的观察再证明这个预测器准确（同源自证）。至少一个参考模型/录制真值必须独立于 Motor 预测模型。

### 9.2 必做混沌矩阵

| 维度 | 具体情景 | 判据 |
|---|---|---|
| 延迟 | 0/25/75/150/300/600 ms 单程观测或独立抖动；长尾、顺序颠倒、burst/blackout | 控制器不会按晚到的旧观测恢复旧输入 |
| 观察 | 2/5/10/20 Hz 下采样 + event-only；停顿后补发、观测变成未知 | 时间来源显式；超龄禁危险动作；静止低发包不误报卡住 |
| helper | 接收后回执丢失、重复 commandId、死锁、重启、端点 EOF/未 EOF、旧 generation 延迟 | 非幂等事件不自动重播；独立释放机制的 fake deadline 成立 |
| 焦点/UI | 运动中 Alt+Tab、切聊天、断焦点、窗口重建、最小化 | 焦点错时输入被拒并发布释放结果；UI 冲突不误发按键 |
| 物理 | 突然低速/高惯性/后退/转角碰撞/半砖/头顶净空变化/地面丢失 | 不越过已知安全包络，未知立即降级 |
| 服务器 | 位置回正、旧连接观察晚到、维度/身体 epoch 切换 | 原计划失效；新会话不重放旧动作 |
| 并发 | Planner 卡顿、operator 取消、旧 finally、新 owner 接入 | 单入口、不跨代清键、不丢最新撤销命令 |
| 校准 | yaw 收益反向、为 0、左右不对称、饱和、改灵敏度后旧 gain | 无响应自动降级，不强行执行 |

### 9.3 指标与可验收候选

| 指标 | 定义 | 离线建议基线（非 26.3 达标宣称） |
|---|---|---|
| `poseErr` | `||p_actual - p_target||`，仅在独立真值可用时 | 安全平地单步 P95 ≤ 0.25 block（基准目标） |
| `yawErr` | `abs(wrapTo180(yaw_actual-yaw_target))` | P95 ≤ 2°（对已校准角度与无干扰静态 profile） |
| `overshoot` | 目标区域之外最远位移；分别测位置和角度 | 平地 P95 位置 ≤ 0.20 block（设计目标） |
| `stopDistance` | 发送停止命令至实体最终稳定的实际位移 | 记录 P50/P95/P99/最差、按速度/模式分层；不能预设所有模式同一常数 |
| `releaseLatency` | 触发 fault 至 helper 报告已释放的单调耗时 | 人为停止 P99 < 250ms 候选；helper 失联/OS 调度受限要单列 |
| `staleActionCount` | 快照过期/旧 epoch 后仍产生**新**控制副作用 | 0（严格合同，混沌测试） |
| `nonIdempotentReplay` | 状态不确定时同一逻辑点击/相对鼠标重复发送 | 0（严格合同） |
| `collisionRiskEscapes` | 安全边界不满足时仍继续向危险方向推进 | 0（在合成覆盖的范围内） |
| `stuckLatency` | 有**新证据**但无应有进展，到 `STUCK` 分类的耗时 | 随观测频率配置；强制输出误报率与漏报率 |
| `recoverySuccess` | 原语失败后在预算内到达新稳定端点的比例 | 按地形/延时/错误类别分层；不以样本总体平均混淆 |
| `commandAckToEffect` | OS helper ack 至有可识别游戏效果的耗时 | 未实机时只能给 synthetic；不得写实测数值 |
| `observationAge`/`controlJitter` | 收到观测至发控制年龄、控制计划期与实际回调误差 | P50/P95/P99/最大值与丢观察率共同报告 |

测试不只要看均值：对停止距离、角度超调尤其要看**尾部极值**。训练集/控制器物理模型与测试真值不能完全相同；人为引入未建模延时才有意义。

### 9.4 未来真实客户端必须验证的十项（明确不在本轮执行）

1. 26.3 原版 SDL 构建/Windows 输入后端实际版本。
2. Window focus / gameplay / pause / chat / inventory 行为与 SDL 状态同步。
3. Windows VK/扫描码、游戏自定义绑定、布局切换下操作是否生效。
4. `SendInput MOUSEEVENTF_MOVE` 的实际 yaw/pitch 响应；单击与长按是否同路径。
5. 2 轴鼠标增益的大小、非线性、加速/平滑、抖动与各种分辨率/模式影响。
6. 移动 packet field 与 26.3 专用解码器的 packet ID/schema/标志位。
7. 网络速度/时间窗下位姿报告到达率，静止时发送策略。
8. 服务端 correction、碰撞与落地 flag 的实际相互关系。
9. 不同地表/水中/空中/潜行/冲刺下停距、稳定时间、实际碰撞体。
10. helper/Node 崩溃、锁屏、窗口丢焦点、远程桌面、设备切换时 OS 按键释放是否可保证。

**严格晋升策略**：完成离线测试仅得 `contract_verified`；提供真实 26.3 + 固定配置 + 可复现 trace 才能得 `client_calibrated`；跨配置实验后才可得 `production_enabled`。三者不能互相替代。

## 10. 推荐实施边界与优先序

只增加/修订 Motor 子层、LocalControlView adapter、InputGateway-Helper 交接和 trace 测试；原有 Planner/Skill/Runtime/SQLite 与 owner/epoch 语义保持。

**阶段 A（零真实输入也可完成）**：确保全链路 source/evidence 语义，拒绝把当前帧元数据当位姿；将 `Motor.send accepted→succeeded` 改为相位驱动的观察验收；helper lease 的时钟域、owner/fencing 与独立释放设计一致；改进 fake 模式时序测试。

**阶段 B（26.3 解析数据验证后）**：选取最少但明确核验的运动/纠正/区块/UI 状态字段，构建 LocalControlView 和 drift/correction 识别；对缺失字段 fail-closed；其余用于陆地短步位移与角度估计的局部数据有明确降级路径。

**阶段 C（将来用户允许实机校准后）**：先验 Win32→SDL3 的事件消费/键码/鼠标增益能力，再逐项启用原语：`stop → turn → flat ground approach → jump → edge approach → aim/use`。每项都带测试覆盖、失败签名、证据等级和可撤销 profile。该顺序是推荐，并非本轮已运行测试。

**总决策**：在没有已核验 Java 26.3 运动观测、没有证实 SDL3 消费了 Win32 鼠标相对事件、且 helper 过期 held 输入的独立 watchdog 尚未完成前，**不应把当前 Motor 标记为现实闭环可用**；但完整的闭环协议、控制 FSM、测试框架和安全控制合同完全可以先在离线环境做出来。
